# Patient Zero

Изометрическая игра про распространение заражения среди 500 жителей и управление ордой.

## Запуск

Проверено на **Godot 4.7.2 stable из Steam**. Импортировать `project.godot` из этой папки и нажать F5.
Рабочий проект: `E:/Games/P_Zero/files/patient-zero/patient-zero`.

## Текущие правила

- Эвакуации, КПП и лимита времени нет.
- Победа — охват 100% населения: заражённые, включая людей без симптомов, плюс погибшие.
- Поражение — смерть игрока от огня полиции. Ареста нет.
- Роль убийств в победе ещё предстоит оценить при настройке баланса.

## Управление

- WASD — движение; Shift — бег.
- Удерживать ЛКМ — захват; Space — остановить шкалу.
- ПКМ — движение / атака орды; F — следовать; H — удерживать.
- Alt во время бега — бросок к цели.
- Esc — меню; R — новый забег.

## Переделки и дорожная карта

В меню Esc доступны вкладки **Переделки** и **Дорожная карта**.
Дорожная карта — четыре плашки-категории в ряд. Нажатие на заголовок раскрывает
пункты с чекбоксами вниз; повторное нажатие сворачивает категорию.
Галочка означает «проверено и принято». Статус реализации показан отдельно.
После изменения галочек нажать **Сохранить отметки**. Они сохраняются между забегами и запусками.

Общий источник для Codex и Claude: `data/development_plan.json`.
В рабочем проекте меню меняет `accepted` в этом файле; агент может изменить то же поле напрямую после приёмки.
В экспортированной игре отметки хранятся локально в `user://development_acceptance.json`.
Раздел возможных механик — идеи для обсуждения, а не обязательный состав демки.

## Проверки

Из папки проекта в PowerShell:

```powershell
& 'D:/Steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe' --headless --path . --editor --quit
& 'D:/Steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe' --headless --path . --script res://tests/stage1_checks.gd
```

Успех сценария: `STAGE1_CHECKS_COMPLETE failures=0`, без `SCRIPT ERROR` / `ERROR`.
Сценарий проверяет правила и меню; игровой баланс принимается отдельно.
Во время теста не редактировать файл плана: одна отметка временно меняется для проверки сохранения и затем восстанавливается.

Снимки интерфейса: `tests/capture_development_menu.gd` (запуск с графикой).
Параметры баланса: `scripts/tuning.gd`. Контекст разработки: `CLAUDE.md`.
